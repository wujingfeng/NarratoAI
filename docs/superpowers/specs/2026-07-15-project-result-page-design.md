# 项目结果页设计说明

## 目标

在 `docs/web/homepage-prototype/` 新增 `/dashboard/projects/overlord/result`，结构化还原 `13-project-result-desktop.png` 的项目成片结果视图，并让“我的项目”第一条已完成项目可进入该页面。

## 页面结构

- 保持现有工作台壳层，复用 `DashboardSidebar`、`DashboardHeader` 与 `DashboardMobileNav`。
- 顶部工作区显示面包屑“我的项目 / 霸总短剧解说 01”，右上继续复用创作点、充值和账户区域。
- 主结果卡由项目标题、规格、完成状态、主要导出按钮、真实视频播放器、结果操作区、任务步骤与操作日志组成。
- 底部为创作点消耗和项目摘要两张信息卡。
- 桌面布局贴近 1487×1058 参考密度；中窄屏折为单列；移动端使用底部导航并确保无横向溢出。

## 视觉方向与 Token

- 延续工作台深海军蓝背景与极细蓝灰边框，面板使用半透明深色渐变。
- 主强调色为紫色到蓝色渐变；完成态与步骤轴使用青绿色。
- 结果页使用 `public/media/project-result/` 下的专属成片与字幕，其素材来源于 `public/media/narration-editor/` 的现有真实视频并经裁切、转码生成；参考截图只用于视觉比对，绝不进入页面组件树或成为交付资产。

## 交互

- 播放器使用原生 `<video>`，自定义播放/暂停、静音和全屏控制，同时保留键盘可访问性；播放器时长与真实媒体 metadata 均为精确 85 秒，进度由 metadata 驱动并钳制在 0–100%。
- “导出视频”下载 `1080×1920`、85 秒的项目专属 MP4；“下载字幕”下载 MIME 为 `text/vtt` 的项目专属字幕。
- “分享项目”“再次编辑”与账户区未接入能力通过 `DashboardToast` 给出原型反馈。
- 项目列表第一条“查看结果”使用路由链接进入结果页，其余项目行为保持现有逻辑。

## 可维护性边界

- 页面数据单独存放于 `src/data/projectResultData.js`。
- 播放器和信息卡拆分为结果页专属组件；页面只负责布局、Toast 与播放器状态协调。
- 样式集中在 `src/styles/project-result.css`，不侵入既有项目页样式。

## 验收标准

1. `/dashboard/projects/overlord/result` 可直接访问、刷新，标题与路由焦点正确。
2. 工作台左侧“我的项目”保持选中，右上账户区域与移动底栏复用。
3. 项目列表第一条“查看结果”可进入结果页。
4. 播放、暂停、静音、全屏和下载具备可操作行为；未接入操作显示 Toast。
5. 1487×1058 桌面截图无横向溢出，主要构图与参考图一致；390px 移动布局可用。
6. 不使用参考截图、局部截图、base64、canvas、CSS 位图背景或 SVG 内嵌位图伪造页面。
7. 删除或隐藏所有参考图后，页面仍不缺失任何主体内容。
8. 结果路由可直接访问并刷新；视频与字幕请求返回 2xx 和合理 MIME，视频 metadata 约为 85 秒。
