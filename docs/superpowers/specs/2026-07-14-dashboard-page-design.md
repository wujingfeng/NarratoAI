# 工作台首页还原设计规格

## 1. 目标

在现有 `docs/web/homepage-prototype/` React + Vite 项目中新增独立工作台首页，以以下两张原型图作为对应视口的视觉参考：

- 桌面端：`docs/web/prototypes/b-style/04-dashboard-desktop.png`
- 移动端：`docs/web/prototypes/b-style/28-dashboard-mobile.png`

官网首页继续位于 `/`，工作台新增于 `/dashboard`。官网中任意“开始创作”按钮均通过客户端路由进入 `/dashboard`；工作台左上角“影创工坊”品牌 Logo 区域作为真实链接返回 `/`。

本次成功标准：

- 桌面端高保真还原参考稿中的侧栏、账户区、促销 Banner、创作入口、工具入口、项目、创作点和灵感模块。
- 移动端按移动参考稿进行内容取舍和响应式重排，而不是缩放桌面截图或固定画布。
- 页面使用结构化、可编辑、可维护的 React 组件与 HTML/CSS 实现，所有可操作入口都有真实交互反馈。
- 路由支持直接访问、刷新、浏览器前进与后退，不以组件内布尔状态伪造页面切换。
- 删除或隐藏全部参考图后，最终页面仍然完整，且不缺失任何主体内容。

## 2. 范围与非范围

### 2.1 本次范围

- 为项目引入 `react-router-dom`，建立官网与工作台的 SPA 路由。
- 保留现有官网首页并接入 `/`。
- 新增 `/dashboard` 工作台概览页。
- 将官网所有文案或语义为“开始创作”的按钮统一改为跳转 `/dashboard`。
- 实现桌面侧栏、顶部账户区、工作台主体模块和移动端底部导航。
- 使用集中 Mock 数据呈现余额、项目状态、消耗和案例灵感。
- 对已存在目标页面的入口执行真实路由跳转，对尚无页面的入口显示轻量“功能建设中” Toast。
- 实现 Banner 关闭、卡片状态、键盘操作、焦点样式和 reduced-motion 降级。
- 增加路由、响应式、交互、构建和反贴图验证。

### 2.2 明确不做

- 不接入登录、用户、项目、创作、积分、支付、充值或媒体处理后端接口。
- 不实现新建创作流程、项目详情、设置、会员、充值和各工具的目标业务页面。
- 不为未实现功能创建无内容的占位路由。
- 不改写现有官网的信息架构、Demo 浏览、锚点导航和视频弹窗等非“开始创作”行为。
- 不将桌面参考稿机械缩小为移动端，不使用固定截图尺寸锁死布局。
- 不使用参考图或参考图裁片作为页面资产，不做截图贴图式还原。

## 3. 路由方案

采用 React Router 的 `BrowserRouter` 单页路由方案。

| 路径 | 页面 | 行为 |
| --- | --- | --- |
| `/` | 现有官网首页 | 保留现有区块、锚点导航和交互 |
| `/dashboard` | 新增工作台概览 | 渲染桌面或移动响应式工作台 |
| 其他未匹配路径 | 轻量 404 页面 | 提供返回官网和进入工作台的操作入口，不得白屏 |

路由原则：

- 站内路由使用 `Link`、`NavLink` 或 `useNavigate`，不使用 `window.location` 强制整页刷新。
- `/` 与 `/dashboard` 必须支持地址栏直接访问和刷新；部署/预览环境需使用 SPA fallback。
- 路由切换后将页面滚动恢复到顶部，并确保焦点/页面标题提供可感知的页面变化。
- 当前已确认存在的目标路由只有 `/` 与 `/dashboard`。因此，工作台 Logo 可直接返回 `/`；其余尚未实现的业务入口本阶段显示 Toast，不跳往空白页。
- 后续新增真实页面时，可在统一导航配置中为相应入口补充 `to`，入口自动从 Toast 行为切换为路由跳转。

建议结构：

```text
BrowserRouter
└── Routes
    ├── /           -> HomePage（现有官网 App 内容）
    ├── /dashboard  -> DashboardPage
    └── *           -> NotFoundPage
```

## 4. 官网入口跳转

官网范围内所有“开始创作”入口统一进入 `/dashboard`，至少覆盖：

- Hero 主 CTA“开始创作”。
- Demo、能力区或模板卡片中语义明确为开始创作、使用模板继续创作的入口。
- 页面底部最终 CTA“开始创作”。
- Header、Footer 或后续已存在区块中任何同语义入口。

实施时不能只按当前组件名枚举，应同时检索可见文案、`aria-label` 和回调语义，确保没有继续弹出旧的“正式工作台接入后继续”Toast。以下行为保持原样：

- “查看 Demo”继续滚动到 Demo 区域。
- 产品能力、案例等官网锚点继续执行页内导航。
- 登录、视频播放、Tab 切换等与开始创作无关的行为不因路由接入而改变。

## 5. 页面信息架构

### 5.1 桌面端 `/dashboard`

页面采用“固定左侧导航 + 顶部账户区 + 可滚动主内容”的三段结构。

#### 固定左侧导航

- 左上角“影创工坊”Logo 与品牌文字组成完整链接，点击返回官网 `/`。
- 主导航包含工作台概览、新建创作、我的项目。
- 工具导航包含短剧解说、视频翻译、短剧混剪。
- 辅助导航包含创作点、设置、会员入口。
- 当前工作台概览项具有稳定的选中态和 `aria-current="page"`。
- 未实现入口点击后显示“功能建设中” Toast。

#### 顶部账户区

- 位于主内容上方右侧，展示创作点余额 `1,280`、去充值按钮和用户头像入口。
- 余额区、充值按钮和头像均使用真实可聚焦元素；未实现时通过 Toast 反馈。
- 品牌 Logo 不迁移到右上角，返回官网的品牌入口明确位于左上角侧栏区域。

#### 主内容区

按视觉层级包含：

1. 促销 Banner，带主文案、辅助信息、装饰视觉、轮播指示和关闭按钮。
2. 大型“新建创作”主入口。
3. 短剧解说、视频翻译、短剧混剪三张快捷工具卡。
4. 最近项目列表，展示完成、处理中、草稿状态和处理中进度。
5. 创作点使用情况，展示当前余额、月度消耗、进度/环形统计。
6. 案例灵感列表，展示三条示例内容。
7. 底部品牌文案。

桌面内容应使用 Grid/Flex 自然排布，在主内容变窄时先重排卡片而非产生横向滚动。

### 5.2 移动端 `/dashboard`

移动端以 `28-dashboard-mobile.png` 为视觉依据，进行独立的信息优先级重排：

- 顶部仅保留品牌、创作点和头像；品牌可点击返回 `/`。
- 促销 Banner、新建创作、快捷工具、最近项目、月度消耗纵向排列。
- 快捷工具卡片允许横向触摸滚动，并提供可见的后续内容提示或合理露出。
- 隐藏桌面侧栏、桌面案例灵感和环形统计详情，仅保留核心消耗摘要。
- 底部固定“概览 / 新建 / 项目 / 我的”导航，概览为当前项。
- 主内容底部 padding 必须覆盖底部导航高度与 `env(safe-area-inset-bottom)`，不能遮住最后一项内容。
- 触控目标不小于 44 × 44 CSS px；页面在 320px 及以上宽度不得横向溢出。

### 5.3 中间断点

- 宽桌面：侧栏固定，主内容采用多列布局。
- 紧凑桌面/平板横屏：缩小侧栏与 gutter，统计/灵感模块可降为两列或单列。
- 平板/移动：隐藏桌面侧栏，启用移动 Header 和底部导航，主内容单列。
- 断点必须依据内容容纳能力确定；参考实现可在约 `1024px` 切换导航形态，但不得依赖单一截图宽度。

## 6. 组件与数据边界

建议组件划分：

| 组件 | 职责 |
| --- | --- |
| `DashboardPage` | 页面状态、布局编排、Toast 与 Banner 状态协调 |
| `DashboardSidebar` | 桌面品牌和导航；当前项高亮；品牌返回官网 |
| `DashboardHeader` | 桌面/移动账户信息和移动品牌入口 |
| `PromotionBanner` | 促销内容、CSS/SVG 装饰、指示器和关闭操作 |
| `CreationEntryCard` | 工作台首要“新建创作”入口 |
| `ToolQuickStart` | 三种工具卡与移动横向滚动容器 |
| `RecentProjects` | 项目列表、状态、缩略图降级和进度展示 |
| `CreditsOverview` | 余额、月度消耗、环形统计或移动摘要 |
| `InspirationPanel` | 桌面案例灵感列表 |
| `DashboardMobileNav` | 移动端固定底部导航与安全区 |
| `DashboardToast` | 未实现功能的统一可访问反馈 |

导航项、工具、项目、创作点和案例灵感数据集中放在独立配置/数据模块中。组件不应散落重复文案、目标路由和状态颜色。导航配置建议统一表达：

```js
{
  id: "projects",
  label: "我的项目",
  icon: FolderIcon,
  to: null,
  unavailableMessage: "我的项目功能建设中",
}
```

若后续真实路由存在，只需将 `to` 改为目标路径，不改变组件结构。

## 7. 交互设计

- 工作台左上角 Logo：真实站内链接，跳转 `/`。
- 官网任意“开始创作”入口：真实路由跳转 `/dashboard`。
- 工作台已存在目标路由的入口：直接路由跳转。
- 工作台未实现入口：保持当前页面，显示轻量“功能建设中” Toast；不能使用无反馈的空链接。
- Banner 关闭：点击后从布局中移除，内容自然上移；本阶段无需持久化到本地存储。
- Banner 轮播指示：保留参考稿视觉；首版不自动轮播，不制造虚假定时行为。
- 最近项目与工具卡：提供 hover、focus-visible、active 状态；整卡可点击时须使用单一明确的按钮或链接语义，避免嵌套交互元素。
- 移动工具区：支持原生横向触摸/触控板滚动和 scroll snapping（如使用，不得强制抢夺纵向滚动）。
- Toast：自动关闭，也可提供关闭按钮；重复点击时更新消息并重置计时。
- 浏览器前进/后退：官网与工作台状态切换正确，不重复挂载多个 Toast 或监听器。

## 8. Mock 数据

本阶段使用静态前端 Mock 数据，文案与数值以参考稿为基础：

- 创作点余额：`1,280`。
- 月度消耗：`240` 创作点。
- 最近项目至少覆盖三种状态：完成、处理中、草稿。
- 处理中项目进度：`66%`，同时提供可见文本，不能只依赖进度条宽度传意。
- 快捷工具：短剧解说、视频翻译、短剧混剪。
- 案例灵感：三条示例内容。

Mock 数据不模拟请求延迟、不写入浏览器持久层，也不暗示充值或创作操作已完成。金额、余额、项目状态仅用于视觉原型。

## 9. 视觉 Token

在现有首页深色视觉基础上增加工作台 Token，避免各组件硬编码近似值。建议语义变量如下，最终数值可在视觉对比中微调：

```css
:root {
  --dashboard-bg: #050812;
  --dashboard-surface: #0a1020;
  --dashboard-surface-raised: #10182a;
  --dashboard-surface-muted: rgba(16, 24, 42, 0.72);
  --dashboard-border: rgba(142, 166, 211, 0.15);
  --dashboard-border-strong: rgba(132, 156, 255, 0.3);
  --dashboard-text: #f5f7ff;
  --dashboard-text-muted: #8e9ab3;
  --dashboard-primary: #6f6cff;
  --dashboard-primary-strong: #8a5cff;
  --dashboard-cyan: #21c7e8;
  --dashboard-orange: #ff9a55;
  --dashboard-success: #38d39f;
  --dashboard-warning: #ffb35c;
  --dashboard-radius-sm: 10px;
  --dashboard-radius-md: 16px;
  --dashboard-radius-lg: 22px;
  --dashboard-shadow: 0 18px 50px rgba(0, 0, 0, 0.28);
}
```

视觉规则：

- 页面底色为近黑蓝，面板使用层级明确的深蓝/半透明表面。
- 主操作使用蓝紫渐变；视频翻译使用青蓝强调；短剧混剪使用克制橙色强调。
- 字体沿用项目现有字体栈，使用字号、字重、行高 Token 形成标题、正文、说明和数值层级。
- 卡片边框、圆角、阴影、间距与交互态统一，不为每张卡单独发明一套样式。
- 图标优先使用既有 `@phosphor-icons/react`；装饰图形可以使用可编辑 CSS 或纯矢量 SVG。
- 动效仅用于进入、hover、进度和 Toast，持续动画必须克制。

## 10. 图片资产边界与反贴图要求

### 10.1 严格禁止

- 禁止把 `04-dashboard-desktop.png`、`28-dashboard-mobile.png` 或它们的任何裁片加入页面、`public/`、组件树或 CSS。
- 禁止使用整张或局部截图、`background-image: url(...)`、`data:image`、base64、canvas 截图绘制、SVG 内嵌位图、bitmap fill 或透明覆盖层伪造页面。
- 禁止将文字、按钮、卡片、导航、项目状态、统计图或促销信息烘焙到图片中。
- 禁止把参考图放在最终页面底层，再用透明热点模拟交互。

### 10.2 必须结构化重建

- 文本必须是真实文本节点。
- Logo 区、按钮、卡片、侧栏、底部导航、进度条和关闭按钮必须是真实 HTML/React 元素。
- 布局使用 Grid、Flex、sticky/fixed、媒体查询和容器约束。
- 环形统计使用 CSS `conic-gradient`、可编辑 SVG 路径或等价结构化实现，不使用统计截图。
- 促销 Banner 的晶体/光效优先使用 CSS 与纯矢量 SVG，且 SVG 不得嵌入位图。

### 10.3 允许的图片资产例外

- 项目缩略图、案例内容图、用户头像、真实 Logo 图形如确属产品内容资产，可使用真实 `<img>`。
- 实现前应优先复用项目既有内容资产，不从参考图裁切。
- 图片必须具有适当 `alt`；纯装饰图使用空 `alt` 或 `aria-hidden="true"`。
- 图片加载失败时显示结构化渐变占位块和可读标题，不破坏布局。

交付前必须删除或隐藏所有参考图并复核：**删除参考图后，最终结果不能缺失任何主体内容。**

## 11. 错误处理与降级

- 图片加载失败：展示渐变占位块，不出现破图图标或布局塌陷。
- 未实现入口：统一 Toast 反馈，不抛错、不跳空白页。
- 未知路由：显示轻量 404，并提供返回官网与进入工作台的真实链接。
- Banner 关闭后：主内容自然补位，不遗留空白容器。
- 极窄屏或长文案：允许合理换行/省略，不能覆盖图标或超出视口。
- JavaScript 动画不可用或 `prefers-reduced-motion: reduce`：页面保持静态完整，关闭非必要过渡和滚动动画。
- 内容图不可用：核心信息仍由文本、状态与结构化控件表达。

## 12. 可访问性

- 使用 `header`、`nav`、`main`、`section`、`aside` 等语义结构，并提供唯一、层级合理的页面标题。
- Logo 使用带可读名称的链接；仅图标按钮（Banner 关闭、Toast 关闭等）必须提供 `aria-label`。
- 当前导航项使用 `aria-current="page"`；不能仅凭颜色表达选中态。
- Toast 容器使用 `role="status"` 或 `aria-live="polite"`，避免抢夺焦点。
- 项目进度使用原生 `progress` 或等价 ARIA 语义，并展示 `66%` 可见文本。
- 所有交互元素可通过 Tab 到达，具有清晰 `:focus-visible` 样式，键盘激活行为与点击一致。
- 文本与背景、状态颜色与背景达到合理对比度；状态不能只依赖颜色，应配合图标或文本。
- 移动底部导航和横向卡片满足触控尺寸；固定导航不得遮挡缩放后的内容。
- 进入新路由时更新 `document.title`，并保证屏幕阅读器能够识别页面已经变化。

## 13. 验证计划

### 13.1 构建与静态检查

- 在 `docs/web/homepage-prototype/` 执行 `npm run build`。
- 增加工作台/路由验证脚本，或扩展现有验证机制覆盖本规格。
- 搜索源代码和静态资产，确认不存在参考图文件名、参考图复制文件、`data:image`、base64、canvas 截图及 SVG 位图嵌入。
- 检查 Dashboard CSS 不使用 `background-image: url(...)` 模拟页面主体。

### 13.2 路由与交互自动化

使用 Playwright 至少验证：

1. `/` 正常渲染现有官网。
2. 官网每个“开始创作”入口均进入 `/dashboard`。
3. `/dashboard` 可直接访问和刷新，且不会白屏。
4. 工作台左上角“影创工坊”Logo 返回 `/`。
5. 浏览器前进、后退在 `/` 与 `/dashboard` 间正确切换。
6. 未实现入口不改变路由，并显示可访问 Toast。
7. Banner 可关闭，关闭后布局补位。
8. 移动底部导航当前项正确，未实现项显示 Toast。
9. 页面运行期间无 `console.error`、page error、未处理 Promise 或资源 404。
10. 官网原有锚点、Demo、Tab、视频等非开始创作行为没有回归。

### 13.3 视觉与响应式验证

截图保存到 `docs/web/homepage-prototype/artifacts/`，不注入页面：

- 桌面基准：`1487 × 1058`。
- 移动基准：`390 × 844`，并补充完整长页截图。
- 至少一个平板/中间宽度（例如 `768 × 1024` 或 `1024 × 768`）。
- 至少一个宽桌面视口，检查主内容最大宽度与侧栏关系。

每个视口检查：

- 无横向滚动，`scrollWidth <= clientWidth`。
- 侧栏、Header、底部导航与主内容不互相遮挡。
- 移动底部安全区和最后一项内容完整可见。
